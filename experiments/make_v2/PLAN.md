# make_v2 실행 계획과 승인 상태

> 최종 종료 상태: 추가 학습은 종료했다. 0~2단계와 고정 체크포인트 최종 테스트만 수행하며, Stage 3·H2 등은 미실행으로 종료한다. 아래는 사전 계획 기록이다. 최종 상태는 저장소 README와 reports/final_results.md를 따른다.


현재: 2026-10-22 사용자 승인으로 0.5~2단계를 중간 승인 없이 연속 실행한다. 3단계와 최종 test는 별도 승인 대상이다.

가설은 분리한다. 데이터 처리는 새 Flat−V1 Flat, 계층은 B−A와 C−D, 가중치는 D−A와 C−B로 판정한다. 계층 효과가 없더라도 데이터 처리 개선을 그 근거로 쓰지 않는다.

고정: splits 유지(train 82929 / val 17771 / test는 최종 승인 전 접근 금지), ImageNet ResNet-18, AdamW 3e-4, weight decay 1e-4, cosine, batch 64, 30 epoch, 224px, bf16, validation Macro-F1 최고 체크포인트. V1 체크포인트 보존. val/test 이미지·라벨 수정 금지. 오답이라는 이유로 삭제 금지.

0단계 결과: result_full/make_v2/stage0/README.md. 사진·캐시·로그는 runs_full/make_v2/stage0/. 모든 421장 화면 검토 완료. 해시 후보는 670쌍이며 31쌍만 추가 시각 대조했다. 전체 중복 확정 수와 혼동하지 않는다.

## 0.5단계: 텐서 캐시 검증 (신규, 실행 승인됨)

목적은 반복 JPEG 디코딩/텐서 변환 비용을 줄이는 것이다. 분류 성능 개선 가설과 분리된 실행 최적화이며, 아직 캐시 구현·벤치마크·전체 변환을 수행하지 않았다.

1. 학습 세트만 사용해 소규모 대표 표본을 고정한다. 크기/종횡비가 다양한 표본에서 JPEG 읽기, RGB 디코딩, 증강, 배치 공급, GPU 연산 시간을 나눠 측정한다. 데이터 로딩이 병목인지 먼저 확인한다. 테스트 파일/이미지는 접근하지 않는다.
2. 기존 PIL 디코딩과 같은 RGB 픽셀을 원본 해상도의 uint8 텐서(CHW)로 한 번 저장한다. 이미지별 작은 .pt 파일 대신 여러 이미지를 묶은 데이터 파일과 위치·shape 인덱스, memory map 방식을 우선 검토한다. 캐시에는 원본 식별자·크기·dtype·디코더 버전·분할 지문·완료 상태를 기록한다. 중단 후 이어 만들 수 있게 한다. 원본 파일은 보존한다.
3. 랜덤 크롭/반전/색상/이동 결과와 정규화된 float 텐서는 캐시하지 않는다. 크롭·letterbox·보간 설정은 기존 계획대로 실행 시 적용한다. 증강은 매번 새로 수행하며, 캐시 유무가 샘플 순서나 증강 RNG 소비를 바꾸지 않게 한다. 메모리맵은 읽기 전용으로 열고 in-place 증강 전 복사해 캐시가 변하지 않게 한다.
4. 픽셀 동일성부터 확인한다. 동일 이미지의 기존 PIL RGB 결과와 캐시의 uint8 값/shape가 정확히 같아야 한다. 동일 변환 파라미터로 최종 입력 텐서를 비교하고, V1 seed 0의 고정 검증 표본에서 예측 일치를 확인한다. 원본 텐서를 다시 PIL로 감싸 기존 변환을 유지하는 경로도 비교한다. v2 텐서 변환/GPU 증강으로 전환하면 보간·RNG가 달라질 수 있으므로 자동으로 함께 도입하지 않는다. 입력이 달라지면 캐시 최적화로 채택하지 않고 원인과 별도 변경 여부를 보고한다.
5. 같은 batch/worker/변환 설정에서 기존 JPEG 경로와 캐시 경로를 비교한다. warm-up 뒤 같은 수의 배치를 3회 측정하고 이미지/초, 배치 대기 시간, GPU 연산 포함 시간, CPU/RAM 사용량을 보고한다. OS 파일 캐시가 찬 상태의 재측정도 구분한다. worker 수/pin_memory/persistent_workers 같은 추가 튜닝은 캐시 유무 비교와 분리한다.
6. 표본의 실제 픽셀 수로 전체 train/val 캐시 용량과 구축 시간을 추정하고 사용자 저장 quota도 확인한다. 캐시 생성 시간까지 포함해 예정된 반복 학습에서 이득인지 계산한다. 동일성 통과 + 반복 측정에서 일관된 처리량 향상 + 저장/메모리 여유가 있을 때만 전체 캐시를 구축한다. 이득이 없으면 기존 JPEG 경로를 유지한다. 전체 구축 후에는 인덱스/크기와 모든 캐시 항목의 원본 RGB 일치를 확인한다. 테스트 캐시는 최종 승인 전 만들지 않는다.

산출물: result_full/make_v2/cache_benchmark/에 표본 정의·환경·동일성 검사·속도/용량 결과(CSV/JSON/보고서). 실제 캐시와 임시 자료는 Git 제외 runs_full/make_v2/cache/에 둔다. 실행 후 결과를 보고하고 사용자 승인을 기다린 뒤 1단계로 넘어간다. 캐시 속도 향상을 Macro-F1 향상 또는 계층 가설 지지로 해석하지 않는다.

1단계(연속 실행 승인됨): V1 Flat seed 0 재사용, letterbox Flat seed 0 1회만 실행. 긴 변 224, 비율 유지, ImageNet 평균색 패딩. 학습은 좌우 반전·ColorJitter(.2,.2,.2,.05)와 약한 평행이동/확대 최대 10%. 변환이 차량 끝을 새로 자르지 않도록 합성 순서와 패딩을 먼저 확인한다. 검출기는 사용하지 않는다. 전체 점수, 같은/다른 제조사 오류, 사전 고정 혼동 쌍 방향별 오류, BMW/GMC/VW 정확도를 함께 보고 후 중단. 단일 seed는 선별용이다.

2단계(연속 실행 승인됨): A Flat / B 계층 / C 계층+제조사 가중치 / D Flat+제조사 가중치, seed 0·1·2. 제조사 빈도 역제곱근 가중치, 이미지 평균 1 정규화. hierarchical=name!='flat' 문제를 계층/가중치 별도 플래그로 고친 뒤 D가 Flat 구조인지 smoke로 확인한다. 같은 seed의 백본 초기화·데이터 순서·증강 RNG가 실제로 맞는지 확인한다. letterbox가 이기지 못하면 기존 A/B/C 재사용, D 3회만 실행. 1단계 실행 재사용 시 구조·설정·RNG가 같은지 먼저 확인한다. 평균 paired 차이, paired SD, 개선 seed 수를 보고 후 중단.

사전 효과 기준: 3/3 같은 방향, 평균 차이가 지정한 0.1~0.2%p 수준 seed 변동보다 큼. 통계적 유의성의 증명으로 부르지 않는다. 전체 Macro-F1과 같은 제조사/형제차 목표 지표를 별도 판정한다.

3단계는 선택·별도 승인: 무작위 초기화 Flat/계층×3 seed. 30 epoch 수렴 여부를 먼저 확인한다. 4단계는 모든 설정/체크포인트 확정 및 명시적 승인 후 test 단 1회.

교수님 제안은 위 0.5단계로 구체화했다. 채택한 캐시는 모든 비교 모델에 공통 적용하고, 입력·샘플 순서·증강 RNG를 보존한다.

서버 안전: git clean -fdx 금지, V1 원본 보존, 백업 삭제는 먼저 승인 요청. 긴 학습은 재개 가능한 백그라운드 실행. Git은 소스/CSV/JSON/집계 그림만, 사진/체크포인트/smoke 제외. 커밋 전 status와 staged stat 제시.

구현 세부 고정: letterbox 후 scale 요청 .9~1.1, 이동 ±10%를 샘플링하되 원본 이미지 영역이 출력 경계 안에 남도록 제한한다. 긴 변이 이미 224라 확대는 상한 1로 제한될 수 있다. 사전 지정 형제차는 Silverado↔Sierra와 Tahoe↔Yukon의 4방향이다. seed 0의 Macro-F1이 V1보다 엄격히 클 때만 letterbox를 본 비교에 채택한다. 본 비교에는 평균 차이·paired SD·3/3 방향을 모두 제시하며, 운영상 보수적인 참고 판정은 평균 >0.2%p와 3/3 개선으로 고정한다(통계적 유의성 판정 아님).
